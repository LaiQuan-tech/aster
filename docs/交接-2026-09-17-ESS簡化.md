## 2. 打卡首頁 `/ess`（`app/ess/page.tsx`＋`lib/punch-state.ts`）

四塊：①日期＋秒級時鐘（mount 後才顯示）②大打卡鈕（在內容區、不 fixed）③今日卡「上班 hh:mm／下班 —」④需簽收公告提示（有才出現）→ `/ess/announcements`。拿掉快捷格、待辦、便利貼、公告全文、內部連結。

### 2.1 狀態機 `summarizePunches(records)`（`punch-state.ts:58-80`）
只看 `type in/out`（`break_*`／`outing_*` 一律忽略），依 `punch_at` 升冪，看最後一筆：

| phase | 條件 | nextType | nextLabel | statusLabel |
|---|---|---|---|---|
| `none` | 沒有 in/out | `in` | 上班打卡（primary） | 尚未打卡 |
| `working` | 最後一筆是 `in` | `out` | 下班打卡（primary） | 上班中（顯示「自 hh:mm」＝`workingSince`） |

- `/punch/today` 失敗：`InlineError`＋「重試」，打卡鈕 disabled。

### 2.3 回饋與冷卻 409
- 成功：Toast「上班打卡成功 09:02」／「下班打卡成功 18:05」＋`navigator.vibrate?.(30)`＋先以回傳 `record` 樂觀更新，再 `getPunchToday()` 對齊；成功後 3 秒（`AFTER_SUCCESS_LOCK_MS`）與 `punching` 期間按鈕 disabled。

## 3. 請假／申請 `/ess/requests?kind=…&date=…&id=…`

### 3.1 頁面骨架（`app/ess/requests/page.tsx`）
- `<Suspense>` 包 `RequestsView`（因 `useSearchParams`；Next 16 build 必要）。`?kind` 預設 `leave`、`?date` 需符合 `YYYY-MM-DD` 否則今天、`?id` 傳給「我的申請」高亮並捲到。

- HR／admin 才有「代同仁申請」：五種表單頂端都放 `ProxyPicker`，非 admin 直接回 `null`；勾選展開才第一次抓 `getEmployees()`，濾掉自己與離職者。
- 送出順序（`page.tsx:142-169`）：`createRequest(body)` → 逐檔 `uploadAttachment`（首個失敗即中止並記 warning）→ `invalidateEssState()` → **成功畫面取代表單**（大勾＋「已送出，等待 ○○○ 簽核」，取 `steps` 依 `stepOrder` 排序後 `[0].approverName`，沒有就「已送出，等待主管簽核」＋摘要一行＋「再填一張」「查看我的申請」）→ 捲到頂 → 背景重抓列表。

### 3.2 請假表單（`_components/LeaveForm.tsx`）
欄位順序：假別（必選；空清單時 Select 只有一個「一般請假」）→ 單日｜多日 → 日期（單日一個／多日起迄）→（僅單日）全天｜上午｜下午｜自訂（自訂才出現起訖時間）→ 即時摘要 → 事由（選填 ≤250）→ 附件（只在 `leaveType.requiresAttachment` 出現且必填；≤3 檔、單檔 ≤3MB，`form-shared.tsx:26-27`）→ 送出。
- 互鎖：多日強制全天（`period` 送 `"full"`），切到多日且 `endDate < startDate` 自動補齊；多日不顯示時段列，改提示「多日請假以每天全天計…週末與假日自動略過」。
- 即時摘要：「共 N 天 · X 小時」／error 文案；「已略過 N 天（週末／休息日／國定假日）：日期…」；單日假日 warning；「剩餘 X 小時」或「此假別尚未設定額度」；超過額度顯示紅字「申請時數超過剩餘額度」**但不擋送出**。
- 班表與行事曆（`_components/use-leave-calendar.ts`）：日期變更時按需抓 `getCalendar(year)`（最多跨 2 年）與 `getMySchedules(from,to)`（最多 3 個月）；以 `useRef(Map)` 快取到本次 mount 結束，失敗也快取空值避免重試風暴。

### 3.3 時數規則（純函式 `lib/leave-hours.ts`，19 例測試）
- 當日班別＝`schedules` 的 `shift_id` 對 `shifts`；沒排班→租戶第一個 shift（`created_at` 最早）；沒 shift→`DEFAULT_SHIFT = {start_time:"09:00", end_time:"18:00", break_minutes:60}`。
- `shiftWorkHours = round2(max(0, (end − start − break) / 60))`；`end ≤ start` 視為跨日 +24h（夜班）。
- `halfDayWindow`：`half = round2(shiftWorkHours / 2)`；上午＝`[start, start + half]`、下午＝`[end − half, end]`（日班→上午 09:00–13:00、下午 14:00–18:00 各 4h）。
- `customHours`（自訂時段）：牆鐘差扣除與**假定休息窗**的重疊；休息窗＝`[start + work/2, start + work/2 + break]`（工作時數中點起算，不是班別真實休息時間）。自訂限單日，需起訖時間且結束晚於開始。
- `isWorkday(date, dayType)`：`workday` 裁定→是；`rest_day`／`fixed_holiday`→否；沒裁定→非週六日才是。
- `computeLeaveSegments`：多日逐日產 segment，非工作日進 `skipped[{date, reason: weekend|rest_day|fixed_holiday}]`（顯示「週末／休息日／國定假日」）；**單日不跳過**，改 `warning`「這天是○○，仍可送出」；範圍內無工作日→error「這個範圍沒有工作日」；上限 `MAX_LEAVE_SEGMENTS = 31` 天（超過→「一次最多申請 31 天，請分開申請」）；四捨五入 2 位。
- 後端**信任前端送來的 `hours` 與 `segments`**（與改版前相同），未做後端重算（§9）。

### 3.4 五種申請 body（`lib/request-forms.ts` `buildCreateBody`，21 例測試）
`POST /requests` 的 body；五種都可多帶 `onBehalfOfEmployeeId`（HR 代申請）。

| kind | body 主要欄位 | 必填驗證（錯誤文案） |
|---|---|---|
| `leave` | `startAt`（首段 date+startTime）、`endAt`（末段，跨日 +1 天）、`hours`（`form.hours` 或各段加總，round2）、`segments[{date,startTime,endTime,hours}]`、`leaveTypeId?`、`reason?` | 沒有段→「請選擇日期」；格式錯→「日期或時間格式不正確」；事由 >250→「事由請在 250 字以內」 |
| `fix_punch` | `startAt = endAt = date+time`、`reason`、`segments:[{date, startTime:t, endTime:t, hours:0, type:"in"|"out"}]` | 日期／時間／上班或下班／補卡原因皆必填 |
| `ot` | `startAt`、`endAt`（跨日 +1 天）、`hours = 差 − 休息扣除`、`reason`（自由文字｜「休息扣除：N 分鐘」｜「給付方式：加班費／補休」以「｜」串接）、`payout: "pay"|"comp_time"` | 時數 ≤0→「加班時數需大於 0…」；>16→「加班時數超過 16 小時，請確認起訖時間」 |
| `business_trip` | `tripType: "outing"|"business_trip"`、`startAt`／`endAt`（公出＝單日起訖時間；出差＝起迄日期 00:00–23:59）、`location`、`tripScope`（公出固定 `local`；出差 `local|domestic_intercity|overseas`）、`hours?`、`reason?`、`estimatedCost?`、`advanceRequested?` | 地點必填 ≤250；公出結束需晚於開始；預估花費需 ≥0；勾「需要預支」金額需 >0 |
| `petty_cash` | `startAt = endAt = now`、`reason`、`advanceRequested: amount` | 金額 >0（「請填寫預支金額」）、用途必填（「請填寫用途」） |

補卡的 `segments[].type` 靠 §6 #4 放行後才會被後端存下並在核准時產生對應打卡。

### 3.5 「我的申請」（`_components/MyRequests.tsx`，`GET /requests?scope=mine`）
每列：①`requestTitle`（種類＋假別名）＋狀態 Pill（待簽核 amber／已核准 green／已駁回 red／已撤回 gray）②`describeRequest`：單日「09/18（四）全天 · 8 小時」、多日「09/18–09/20 · 3 天 · 24 小時」、自訂「09/18（四）13:00–17:00 · 4 小時」、加班「… · 2 小時 · 補休」、補卡「09/18（四）上班 09:02」、公出「09/18–09/19 · 台中 · 出差（跨縣市）」、預支「NT$ 3,000」③`approvalLine`：pending「等待 ○○○ 簽核（第 1／2 關）」（`total_steps > 1` 才有關卡）、rejected「駁回理由：…」或「已駁回 · 時間」、approved「已核准 · 09/17 10:21」④footer：「附件 N」、缺憑證（`needsAttachment` ＝ pending 且 leave 且 `requires_attachment && attachment_count === 0`）→ 紅 Pill「缺憑證」＋「上傳憑證」（單檔、>3MB 擋、成功 Toast「已上傳憑證」）、pending「撤回」→ `ConfirmDialog`「撤回這張申請？」→ `cancelRequest` → Toast「已撤回」→ `invalidateEssState()`。
- 頂部 chips 全部｜待簽核｜已核准｜已駁回（**前端過濾**）；預設 30 筆＋「顯示更多（還有 N 筆）」；`?id=` 高亮 ring 並捲入。
- API 新欄位（§6 #5）缺席時：沒有假別名／簽核者／駁回理由，但列表仍可用。

### 3.6 其他四種表單

## 9. 已知限制與待業主確認

1. **請假時數信任前端**：後端存前端送的 `hours`／`segments`，不重算（與改版前相同）。若要防竄改需後端用同一套規則重算（三支資料端點都已開放）。
2. **60 秒打卡冷卻**：可能擋到「下班後立刻再次上班」的誤操作，前端 Toast「剛剛已打過卡」說明即可；要調整改 API 環境變數 `PUNCH_COOLDOWN_SECONDS`，不用改碼。
