## 8. 這個 codebase 的幾個反覆出現的坑

寫給下一個 session，省得再踩一次。

### `supabase-js` 的 select 字串不能折行

```ts
// ❌ 一旦寫成相接，型別退化成 GenericStringError，下游所有 as XxxRow 全爆
const COLS = "id, name, " + "code, status"

// ✅ 必須是單一字串常值
const COLS = "id, name, code, status"
```

踩過兩次（`ADV_COLS`、`PROJECT_COLS`）。

### 軟刪除表的唯一索引必須是 partial index

```ts
// ❌ Postgres 視 NULL 互不相等，兩筆 deleted_at IS NULL 的列反而不會相撞
uniqueIndex("x_uq").on(tenantId, projectId, no, deletedAt)

// ✅
uniqueIndex("x_uq").on(tenantId, projectId, no).where(sql`${deletedAt} is null`)
```

### Express 5 的 `req.params.x` 是 `string | string[]`

repo 慣例是 `req.params.id as string`。

### 「凍結」是這個 codebase 反覆出現的模式

已經用了四次，遇到類似情境就照抄：

| 欄位 | 凍結時機 | 為什麼 |
|---|---|---|
| `advances.balance` | 核銷時 | 事後改單價不該回頭改已結算的餘額 |
| `contracts.stampDutyRate` | 建立時 | 印花稅清單回溯 5～7 年，2021 年的約要用 2021 年的費率 |
| `project_billings.billedAmount` | 標記請款時 | 帳已經出去了，追加減不該讓它回頭變動 |
| `projects.statusEffectiveOn` | 人工填 | 法律日期 ≠ 輸入日期 |

### 有順序相依的 DB 物件放 `packages/db/sql/`，不放 drizzle schema

例：`contracts` 的 CHECK 約束要等舊資料轉換完才能加，
drizzle migration 表達不了這個順序。`sql/0021` 就是為此存在。
