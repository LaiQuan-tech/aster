# 專案分潤與撥款追蹤設計

## 目標

管理員完成專案明細後，可以依參考表格設定專案獎金比例、分配每位成員的分潤、根據客戶實際入帳建立每次獎金撥款，並永久追蹤比例異動與每次撥款快照。年度專案總表、專案申請單、專案獎金總表及放款年度樞紐的欄位與排列以使用者提供的四份檔案為準。

## 已確認規則

- 已發放的獎金批次永久凍結，後續不得覆蓋或重算歷史金額。
- 修改分潤比例後，系統依新比例重算目前累計應得，下一次金額為「新累計應得減歷史已發」。
- 若歷史已發高於新累計應得，下一次顯示負數調整或超發警示，由管理員確認後處理。
- 每次修改比例必須保留操作者、時間、原因、調整前後比例及金額。
- 分潤比例合計不得超過 100%；未滿 100% 的差額顯示為尚未分配。

## 採用方案

擴充現有 `projects`、`project_members`、`project_share_adjustments`、`bonus_runs`、`bonus_run_items` 與放款資料，不另建一套平行系統。現有獎金批次的凍結快照及累計補差算法繼續作為唯一計算來源。

## 資料模型

### 專案獎金設定

- 專案增加 `bonus_rate_pct`，代表參考獎金表的專案獎金比例。
- 獎金池在有 `bonus_rate_pct` 時由目前合約未稅金額乘比例計算；既有只填 `bonus_pool` 的專案保持相容。
- `project_members` 繼續保存目前有效的角色與分潤比例。

### 分潤異動歷程

- `project_share_adjustments` 增加 `change_set_id`，同一次整批儲存共用同一識別碼。
- 異動類型涵蓋獎金比例、獎金池、成員角色、成員比例、加入及移除成員。
- 新增整批儲存 API，在同一交易內驗證比例總和、更新成員並寫入完整異動紀錄。
- 每次整批變更必須填原因。

### 撥款快照

- `bonus_runs` 與 `bonus_run_items` 保持既有 draft、paid、reversal 流程。
- 每筆 item 繼續快照專案、合約額、累計收款、獎金比例、成員比例、累計應得、歷史已發及本次金額。
- paid 後由資料庫 trigger 保護，不允許修改或刪除；錯誤以沖銷批次處理。

## API 與計算流程

1. 管理員在專案分潤表輸入專案獎金比例與各成員比例。
2. 前端即時計算獎金總額、每人成交獎金額及尚未分配比例／金額。
3. 儲存時後端重新計算並驗證，避免只靠前端。
4. 客戶款項入帳後，獎金試算按截至基準日的累計收款比例計算。
5. 本次應發等於新累計應得減所有較早 paid 批次淨額。
6. 建立草稿時保存完整快照；確認撥款後凍結。
7. 之後改比例只改目前設定並寫歷程，不碰過去 paid item。

## 畫面

### 年度專案申請單總表

依參考 Excel 排列：項次、專案單號、日期、客戶、工程名稱、金額、稅金、含稅、已收帳款、應收帳款、已開發票、合約、簽證、發包、業務、備註及各科別金額。採黑框表格、民國日期、千分位與小計／年度總計。系統額外欄位移到表格尾端，不插入參考欄位中間。

### 專案分潤

專案明細新增與獎金總表一致的橫向配置：合約金額、已收款、獎金比例、獎金總額、經理、組員一至四、支援、尚未分配與備註。比例與金額即時連動，整批儲存時要求原因。下方顯示按 `change_set_id` 分組的版本歷程。

### 獎金撥款

試算與批次明細依參考 Excel 顯示：專案單號、工程名稱、含稅、之前請領、之前請領比例、本次請款、本次款比例、累積比例、獎金比例、總獎金、本次獎金、各成員比例／金額、尚未分配與備註。管理員可預覽、建立草稿、確認撥款、匯出 Excel、沖銷及查看歷史。

### 放款年度樞紐

維持一列一專案、十二個月份、合計、代扣與筆數，並從專案明細及撥款紀錄提供連結。未分攤款歸入未指定專案。

### 專案申請單

保留單頁 Aster 表格，確認專案明細、客戶、付款期程、發票、發包、其他支出、利潤與毛利率都由同一份專案資料產生。

## 權限與安全

- HR／平台管理員及既有具分潤管理權限的專案負責人可調整。
- 會計可看金流但不可看他人分潤比例與金額。
- 一般員工只看自己的分潤與已發放歷史。
- 後端強制租戶隔離、專案範圍及百分比驗證。

## 錯誤處理

- 比例超過 100%、不存在的員工、重複成員或缺少變更原因時拒絕儲存。
- 合約額或獎金比例缺失時仍顯示專案，但標示無法試算並略過撥款。
- 收款比例超過 100% 時保留實際數字並顯示警示，不靜默截斷。
- 已發放批次不可編輯；使用沖銷流程修正。

## 測試與驗收

- 純函式測試：獎金池、未分配、累計應得、改比例後補差、超發與四捨五入。
- API 測試：整批分潤交易、必填原因、比例上限、權限、租戶隔離及異動分組。
- 前端測試：表格欄位順序、即時計算、錯誤提示及歷程顯示。
- Excel 測試：欄位、公式／數值、格式、凍結窗格、合計與檔名。
- 完成前跑 typecheck、相關單元測試、build，並以參考檔逐欄人工比對。
