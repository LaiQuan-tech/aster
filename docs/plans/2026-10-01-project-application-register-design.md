# 專案申請單建案與 Excel 總表共用設計

## 目標

管理員在「建立專案」時，直接使用與正式「專案申請單」相同的欄位與版面完成立案。建立後，所有資料立即成為專案明細、專案申請單、年度總表、合約與請款追蹤的共同資料來源。專案首頁下方總表改成與 `AT-114年專案申請單總表.xlsx` 相同的表格結構，點任一專案列即可進入該專案明細。

## 使用者流程

1. 管理員在專案首頁填寫專案申請單式建案表單。
2. 表單涵蓋基本資料、客戶、設計內容、銷售金額、付款階段、協力技師、發包與內部管理欄位。
3. 合約金額可直接輸入；送出時同步建立專案的主合約，未稅、稅額與含稅金額使用同一套財務計算。
4. 建立成功後導向該專案的「專案明細」。
5. 專案頁提供「專案明細」與「專案申請單」兩個頁籤；後者沿用同一筆資料並保留列印功能。
6. 專案首頁下方顯示 Excel 式年度總表。每列、專案編號與工程名稱均可進入專案明細。

## 架構

### 共用表單

將建案與既有申請單欄位整理成共用表單模型與元件。建案模式顯示所有可填欄位及「建立專案」；明細模式沿用既有各卡片的儲存端點。顯示用的 `ApplicationDocument` 繼續作為申請單頁籤與列印輸出，避免建立畫面、編輯畫面與列印畫面各自定義欄位。

### 建立資料流

前端送出完整建案 payload。後端建立專案後同步寫入主合約、付款階段與申請單欄位。回應包含新專案 id 與編號，前端導向 `/admin/projects/:id`。若關聯資料寫入失敗，API 回傳明確錯誤；前端保留使用者輸入，不清空表單，避免重填。

主合約是「合約金額」的正式來源。後續在專案明細修改主合約金額時，申請單、總表、獎金與請款計算都從相同合約資料重新計算，不另存一個可能失去同步的金額欄位。

### 專案頁籤

專案頁上方加入路由式頁籤：

- `專案明細`：`/admin/projects/:id`
- `專案申請單`：`/admin/projects/:id/application`

兩頁共用相同頁首與頁籤。申請單頁保留列印區塊控制和列印按鈕。

### Excel 式總表

抽出既有年度總表的表格呈現元件，專案首頁與年度頁共用。欄位順序、民國日期、金額格式、黑色框線、月份小計與年度總計依 Excel。動態科別接在固定欄位後方。首頁既有案情、年度、排序、封存與預先取號篩選保留，表格資料改由年度總表投影提供。

固定欄位依 Excel A:S 原順序為：項次、專案單號、日期、客戶、工程名稱、金額、稅金、含稅、已收帳款、應收帳款、已開發票、合約、簽證、發包、業務、備註、空調、消防、汙水。Excel 沒有的請款進度、收款進度、狀態與期數不混入這張主表。標題只跨 A:P，保留標楷體、白底、黑色細框、欄寬與列高比例；小計標籤只放在工程名稱欄，不合併 A:E。

整列使用可鍵盤操作的導覽行為，點擊互動控制項不誤觸導覽。編號與工程名稱仍保留明確連結。

## 權限與錯誤處理

- 維持既有 HR／會計／專案權限規則。
- 無財務權限時不洩漏合約、發包或金額資料。
- 送出前驗證必要欄位、百分比合計與非負金額。
- 後端錯誤以欄位或區塊層級文字顯示，建案失敗不清空草稿。
- 舊專案缺少新欄位時以空白或破折號顯示，不阻止進入明細。

## 測試

- API：完整建案 payload、主合約同步、付款階段同步、錯誤回應與權限。
- 純函式：民國日期、金額／百分比、Excel 欄位順序、小計與總計。
- Web：共用建案表單欄位、送出 payload、成功導向、頁籤導覽、整列點擊。
- 回歸：專案明細、申請單列印、年度總表與既有建立／預先取號流程。
- 最終執行 API/Web typecheck、相關 Vitest，並以實際頁面目視比對 Excel 截圖。
