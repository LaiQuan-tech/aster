# 筆電開發環境設定

在新機器上把 aster 跑起來。程式碼走 GitHub,**金鑰不走 GitHub**。

## 1. 前置工具

| 工具 | 版本要求 | 本機目前 |
|---|---|---|
| Node | >= 22（package.json engines） | v24.14.0 |
| npm | 11.9.0（package.json packageManager） | 11.9.0 |

建議用 nvm 對齊:

```bash
nvm install 24 && nvm use 24
npm i -g npm@11.9.0
```

## 2. 取得程式碼

```bash
git clone https://github.com/LaiQuan-tech/aster.git
cd aster
npm install
```

## 3. 環境變數（**這步不能用 git**）

`.env` 在 `.gitignore` 裡,clone 下來不會有。裡面有 `SUPABASE_SERVICE_ROLE_KEY`,
那把鑰匙**繞過所有 RLS**,等同資料庫的 root 密碼。

**傳送方式(擇一,由安全到不安全):**

1. **AirDrop**(建議)— 從主機把 `~/Documents/coding/aster/.env` 直接 AirDrop 到筆電,
   放進筆電的 repo 根目錄。不經過任何第三方伺服器。
2. **從 Supabase 後台重新取得** — 登入 Supabase → Project Settings → API,
   複製 URL / anon key / service_role key,照 `.env.example` 的欄位填。
3. ~~貼在聊天室、Slack、Email、雲端硬碟~~ — 不要。這把鑰匙外洩等於整個
   人事薪資資料庫外洩,而且會留在對方伺服器的記錄裡。

需要的欄位清單見 `.env.example`(已 commit,只有佔位符)。

## 4. 驗證裝好了

```bash
npm run typecheck   # 應該 6/6 通過
npm test            # rules 49 + db 12
npm run build       # 4/4
```

三個都過才算裝好。`typecheck` 若報 `Cannot find module '@hr/rules'`,
代表 turbo 的 build 依賴沒生效——確認 `turbo.json` 裡 `test` 與 `typecheck`
都有 `"dependsOn": ["^build"]`。

## 5. 啟動

```bash
npm run dev
```

- web: http://localhost:3000
- api: http://localhost:3001/health 應回 `{"status":"ok"}`

前端讀不到環境變數的話,確認 `apps/web/next.config.ts` 有載入根目錄 `.env`
(Next.js 預設只讀 `apps/web/` 自己的 `.env`)。

## 6. 兩台機器之間換手

只有 git。動工前 `git pull`,收工前 `git push`。
**不要兩台同時改同一支檔案**——這個 repo 沒有 CI 擋衝突。
