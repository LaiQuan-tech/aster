## 2026-08-26 找到並修正薪資 bug（比原判斷嚴重）

原本懷疑的是「健保眷屬未裁切 3 口上限 → 多扣」，追下去發現是更根本的斷鏈：

`apps/api/src/routes/payroll.ts` 的 `SalaryRow` / `toSalaryStructure` 只映射
method / baseSalary / dailyWage / hourlyWage，**未帶入 labor_insured_salary 與
health_insured_salary**。引擎的保費計算是 `ins && salary.laborInsuredSalary ? ... : 0`，
欄位缺漏時靜默走 0 → **每張薪資單的勞保費、健保費都是 0，實發金額被高估**。

鏈上其他環節都在（寫入端 routes/salary.ts、DB 欄位、引擎計算、rule_config 的
insurance 設定），只有讀取端 mapping 沒接上。以投保 38,200 計，每人每月少扣
955 + 592 = 1,547 元。眷屬則是完全沒計入。

### 修正（commit e01516b, d25f9dc）
- payroll.ts: 補兩個投保薪資欄位的 select 與映射
- payroll.ts: 查 nhi_dependents（insured=true）算眷口數帶入引擎
- payroll.ts: 回傳 `missingInsuredSalary`，列出有保費規則卻未填投保薪資者
- payroll-engine.ts: 健保改走 tw-tax 的 `nhiEmployeePremium`，法定 3 口上限
  裁切邏輯只留一份（原先兩處實作不一致）
- 新增 payroll-engine.test.ts 8 項回歸測試

驗證：typecheck 6/6、rules 49 項（原 41 + 新 8）、db 12 項全過、build 4/4。

### 客戶 25 條開發規則

使用者將依逐字稿拆成 25 條規則逐條討論。第 1 條（2026-09-10）：

> 打卡上限與拆單邏輯：正常出勤卡累計滿 40 小時需自動鎖定/阻擋。超過 40 小時
> 之加班或在家工作時數，系統需自動拆單並轉入隱藏版 Cash 卡（C 單/C 版）紀錄

**處置：拆兩半。**
- 前半（40 小時上限與告警）**做**。§32 月加班上限 46 小時（工會同意可 54，
  每三個月 138 封頂），40 當內部緩衝合理。做成 `work_hour_alerts`，
  36/40/46 三段告警，擋的是再派新工，不是擋紀錄。
- 後半（自動拆單轉隱藏 C 卡）**不做**。理由見
  `01-需求評估與待確認.md`。補充論點：若 40 是每週正常工時（§30 的數字），
  拆完後全公司出勤紀錄都會停在剛好 40 小時、零加班——這種整齊本身就是紅旗。
- 替代方案（已在模型內）：出勤照實記 + `overtime_settlements` 獨立給付紀錄，
  可含現金管道與自己的稅務處理。帳面誠實、錢照付。
