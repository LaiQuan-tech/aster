# 亞斯特 ERP 資料模型 v0

> PostgreSQL DDL。可直接跑在 Supabase 或自架 PG。
> **v0 = 依二手會議說明推導，逐字稿到位後需校正。** 待確認處以 `-- ❓` 標記。
> 建檔：2026-08-24

## 設計原則（先讀這五條，後面 DDL 才看得懂為什麼這樣切）

1. **紀錄真實、給付彈性分離**：出勤紀錄一律完整真實；「怎麼給錢」是另一張表的事。這是取代 C 單拆卡的核心結構。
2. **餘額用流水帳，不用可變欄位**：特休餘額、零用金餘額都由交易明細累加得出，不存一個會被直接 UPDATE 的數字。可稽核、可還原、可回溯任一時點。
3. **三個「哪家公司」是獨立維度**：簽約公司 / 開票公司 / 收付款帳戶所屬公司，各自外鍵。這是規劃書「跨公司金流路由」的正解——用欄位表達，不用備註欄硬塞。
4. **金額可覆寫但必留痕**：系統算出的金額與人工調整後的金額分兩個欄位存，永不互相覆蓋（尤其獎金）。
5. **法務保存的表不做硬刪**：請假單、出勤、公告、薪資一律軟刪 + audit_logs。

## 區塊 A：組織與人

```sql
-- 關係企業（亞斯特、龍權、紅爐、新投資公司）
create table companies (
  id              uuid primary key default gen_random_uuid(),
  code            text not null unique,          -- 'ASTER' / 'LONGQUAN' / ...
  name            text not null,
  tax_id          text,                          -- 統一編號
  is_active       boolean not null default true,
  notes           text,
  created_at      timestamptz not null default now()
);
-- 已確認：跨公司金流性質為集團代收代付，往來債權債務見區塊 L

create table bank_accounts (
  id              uuid primary key default gen_random_uuid(),
  company_id      uuid not null references companies(id),
  bank_name       text not null,
  branch_name     text,
  account_no_enc  text not null,                 -- 加密儲存，不放明碼
  account_name    text not null,
  purpose         text not null,                 -- 'receivable' | 'payable' | 'payroll'
  is_active       boolean not null default true
);

create table departments (
  id              uuid primary key default gen_random_uuid(),
  company_id      uuid not null references companies(id),
  name            text not null
);

create table employees (
  id                  uuid primary key default gen_random_uuid(),
  employee_no         text not null unique,
  name                text not null,
  id_number_enc       text,                      -- 身分證字號，加密
  email               text,                      -- 薪資條寄送目標
  phone               text,
  birth_date          date,                      -- 生日紅包追蹤
  hire_date           date not null,             -- ★ 特休週年制的計算基準
  termination_date    date,
  primary_company_id  uuid not null references companies(id),
  department_id       uuid references departments(id),
  employment_type     text not null,             -- 'fulltime'|'parttime'|'hourly'
  -- ❓ 是否有時薪/日薪制員工未確認，直接影響薪資引擎複雜度
  default_work_mode   text not null default 'office',  -- 'office'|'remote'|'site'
  -- ↑ 涵蓋「在家工作」特別同仁，不需另開隱藏欄位
  status              text not null default 'active',
  created_at          timestamptz not null default now()
);

-- 系統帳號 ↔ 員工（Supabase 走 auth.users）
create table user_accounts (
  id              uuid primary key default gen_random_uuid(),
  employee_id     uuid not null unique references employees(id),
  auth_user_id    uuid not null unique,
  permission_level int not null,                 -- 見區塊 J
  is_active       boolean not null default true
);
```

## 區塊 B：出勤（含 C 單的替代設計）

```sql
-- 原始打卡紀錄：逐日、真實、不可硬刪。這張表永遠記錄實際發生的事。
create table attendance_records (
  id              uuid primary key default gen_random_uuid(),
  employee_id     uuid not null references employees(id),
  work_date       date not null,
  clock_in        timestamptz,
  clock_out       timestamptz,
  break_minutes   int not null default 60,
  work_mode       text not null default 'office',   -- office|remote|site
  source          text not null,                    -- 'device'|'manual'|'import'
  -- ❓ 現有打卡機型號與匯出格式未確認，決定 import 要不要做
  is_amended      boolean not null default false,
  amended_by      uuid references employees(id),
  amend_reason    text,                             -- 補登一律要理由，全數留痕
  created_at      timestamptz not null default now(),
  unique (employee_id, work_date)
);

-- 每日工時計算結果（可做成 materialized view）
-- 正常工時／延長工時分段，供加班費計算（前2h ×1.34、後2h ×1.67）
create table attendance_daily_summary (
  employee_id       uuid not null references employees(id),
  work_date         date not null,
  regular_minutes   int not null default 0,
  ot_tier1_minutes  int not null default 0,   -- 延長工時前 2 小時
  ot_tier2_minutes  int not null default 0,   -- 延長工時第 3-4 小時
  ot_holiday_minutes int not null default 0,  -- 休息日/國定假日
  primary key (employee_id, work_date)
);

-- ★ 取代 C 單：工時照實記在上面，這張表只管「這些超時怎麼結算」
create table overtime_settlements (
  id                uuid primary key default gen_random_uuid(),
  employee_id       uuid not null references employees(id),
  period_start      date not null,
  period_end        date not null,
  overtime_minutes  int not null,
  settlement_type   text not null,   -- 'overtime_pay' 加班費
                                     -- 'comp_leave'   補休（§32-1，轉入 leave_balance）
                                     -- 'flex_absorbed' 已由變形工時吸收
  payment_channel   text,            -- 'payroll' 隨薪匯款 | 'cash' 現金 | 'other'
  -- ↑ 給付管道可彈性；工時紀錄不動。這是「錢照給」的合法出口
  gross_amount      numeric(14,2),
  paid_at           date,
  paid_by           uuid references employees(id),
  approved_by       uuid references employees(id),
  notes             text
);

-- 工時預警：取代「自動鎖卡」，把決策點交還主管
create table work_hour_alerts (
  id              uuid primary key default gen_random_uuid(),
  employee_id     uuid not null references employees(id),
  period_type     text not null,        -- 'week' | 'month'
  period_start    date not null,
  threshold_minutes int not null,       -- 週 40h 正常工時／月延長工時 46h 等
  -- ❓ 原文「每週/每月上限（如 40 小時）」自相矛盾，實際門檻待確認
  current_minutes int not null,
  severity        text not null,        -- 'warning' | 'critical'
  alerted_at      timestamptz not null default now(),
  acknowledged_by uuid references employees(id),
  action_taken    text                  -- 主管的處置：加派人力/轉補休/核准加班
);
```

## 區塊 C：請假與特休（週年制自動聯動）

```sql
create table leave_types (
  id                  uuid primary key default gen_random_uuid(),
  code                text not null unique,   -- 'annual'|'sick'|'personal'|'marriage'|...
  name                text not null,
  is_paid             boolean not null,
  pay_rate            numeric(4,2) not null default 1.00,  -- 普通病假 0.5
  deducts_from_balance boolean not null,       -- 特休/補休 true；事假 false
  requires_attachment boolean not null default false
);

-- 週年制額度：依 hire_date 自動開一個新區間
create table leave_entitlements (
  id                uuid primary key default gen_random_uuid(),
  employee_id       uuid not null references employees(id),
  leave_type_id     uuid not null references leave_types(id),
  period_start      date not null,          -- 到職週年日
  period_end        date not null,
  granted_hours     numeric(8,2) not null,  -- 依年資：6M=3日 1Y=7日 2Y=10日 3Y=14日…
  carried_over_hours numeric(8,2) not null default 0,  -- 未休遞延（勞基法 §38 可遞延1年）
  expires_at        date,
  unique (employee_id, leave_type_id, period_start)
);

create table leave_requests (
  id              uuid primary key default gen_random_uuid(),
  employee_id     uuid not null references employees(id),
  leave_type_id   uuid not null references leave_types(id),
  start_at        timestamptz not null,
  end_at          timestamptz not null,
  hours           numeric(8,2) not null,
  reason          text,
  attachment_url  text,
  status          text not null default 'draft',
                  -- draft|submitted|approved|rejected|cancelled
  approver_id     uuid references employees(id),
  approved_at     timestamptz,
  reject_reason   text,
  deleted_at      timestamptz,     -- 軟刪；法務保存 5-7 年，永不硬刪
  created_at      timestamptz not null default now()
);

-- ★ 餘額用流水帳，不存可變的 balance 欄位
create table leave_balance_transactions (
  id                uuid primary key default gen_random_uuid(),
  entitlement_id    uuid not null references leave_entitlements(id),
  txn_type          text not null,   -- 'grant'發放|'deduct'請假扣除|'reverse'銷假回沖
                                     -- 'carryover'遞延|'expire'失效|'payout'未休折現
  hours             numeric(8,2) not null,   -- 正負號表示增減
  leave_request_id  uuid references leave_requests(id),
  overtime_settlement_id uuid references overtime_settlements(id),  -- 補休轉入
  created_by        uuid references employees(id),
  created_at        timestamptz not null default now(),
  notes             text
);
-- 餘額 = select sum(hours) from leave_balance_transactions where entitlement_id = ?
```

## 區塊 D：薪資（平行雙軌設計）

```sql
create table salary_profiles (
  id                    uuid primary key default gen_random_uuid(),
  employee_id           uuid not null references employees(id),
  effective_from        date not null,
  effective_to          date,                    -- null = 現行
  base_salary           numeric(14,2) not null,
  meal_allowance        numeric(14,2) not null default 0,  -- 伙食津貼（免稅額度內）
  position_allowance    numeric(14,2) not null default 0,
  labor_insurance_grade numeric(14,2),           -- 勞保投保級距
  health_insurance_grade numeric(14,2),
  pension_self_rate     numeric(4,2) default 0,  -- 勞退自提 0-6%
  dependents_count      int not null default 0,  -- 眷屬健保人數
  created_by            uuid references employees(id),
  created_at            timestamptz not null default now()
);

create table payroll_periods (
  id                uuid primary key default gen_random_uuid(),
  year              int not null,
  month             int not null,
  status            text not null default 'draft',
                    -- draft試算|pending_review待審|approved已核定|paid已發放
  calculated_at     timestamptz,
  calculated_by     uuid references employees(id),
  approved_by       uuid references employees(id),  -- 主管審核
  approved_at       timestamptz,
  paid_at           date,
  -- ★ 平行雙軌：導入期同時跑 Excel，差異歸零才准切換
  parallel_run      boolean not null default true,
  unique (year, month)
);

create table payroll_items (
  id                uuid primary key default gen_random_uuid(),
  period_id         uuid not null references payroll_periods(id),
  employee_id       uuid not null references employees(id),
  paying_company_id uuid not null references companies(id),   -- 由哪家公司發薪
  -- 收入
  base_salary       numeric(14,2) not null default 0,
  overtime_pay      numeric(14,2) not null default 0,
  allowances        numeric(14,2) not null default 0,
  bonus_amount      numeric(14,2) not null default 0,   -- 由區塊 H 帶入
  -- 扣項
  labor_insurance   numeric(14,2) not null default 0,
  health_insurance  numeric(14,2) not null default 0,
  income_tax        numeric(14,2) not null default 0,
  leave_deduction   numeric(14,2) not null default 0,   -- 事假/病假扣薪
  advance_offset    numeric(14,2) not null default 0,   -- 沖銷零用金預支
  other_deduction   numeric(14,2) not null default 0,
  net_pay           numeric(14,2) not null default 0,
  -- 雙軌比對
  manual_net_pay    numeric(14,2),                      -- Excel 算出的數字
  variance          numeric(14,2) generated always as
                      (net_pay - coalesce(manual_net_pay, net_pay)) stored,
  email_sent_at     timestamptz,                        -- 一鍵寄薪資條
  unique (period_id, employee_id)
);

create table payroll_item_details (
  id              uuid primary key default gen_random_uuid(),
  payroll_item_id uuid not null references payroll_items(id),
  category        text not null,   -- 'earning' | 'deduction'
  label           text not null,
  amount          numeric(14,2) not null,
  source_ref      text             -- 追溯來源：哪張加班單/獎金/請假單
);
```

```sql
-- 請款期程：使用者自訂期數與趴數，金額自動算
create table billing_schedules (
  id                uuid primary key default gen_random_uuid(),
  project_id        uuid not null references projects(id),
  installment_no    int not null,                  -- 第幾期
  percentage        numeric(6,3) not null,         -- 20.000
  milestone         text,                          -- 「開工款」「完成50%」「驗收」
  -- 系統算的金額 vs 人工覆寫，分開存不互蓋

  unique (project_id, installment_no)

create table invoices (
```

## 區塊 H：專案獎金（隨收款分期拆發）

這是整個模型最關鍵的關聯：**獎金發放由「入帳」事件驅動，不是由「結案」驅動。**

```sql
create table bonus_plans (
  id                uuid primary key default gen_random_uuid(),
  project_id        uuid not null unique references projects(id),
  base_type         text not null,   -- 'contract_amount' 合約金額 | 'gross_profit' 毛利
  -- ❓ 獎金基數怎麼算未確認（合約額 %？毛利 %？扣不扣成本？）→ 影響 base_amount 來源
  base_amount       numeric(14,2),
  pool_percentage   numeric(6,3),    -- 提撥比例
  total_pool        numeric(14,2),
  distribution_rule text not null default 'follow_receipt',
                    -- 'follow_receipt' 隨每期收款同比例拆發（會議共識）
                    -- 'on_completion'  結案一次發
  status            text not null default 'draft',   -- draft|approved|closed
  approved_by       uuid references employees(id),
  approved_at       timestamptz
);

-- 分配矩陣：經理／主辦／支援 各佔幾趴
create table bonus_allocations (
  id              uuid primary key default gen_random_uuid(),
  bonus_plan_id   uuid not null references bonus_plans(id),
  employee_id     uuid not null references employees(id),
  role            text not null,          -- manager|lead|support
  percentage      numeric(6,3) not null,  -- 同一 plan 總和須 = 100（trigger 檢核）
```

### 權限分層（比原規劃多兩層區分）

| Level | 角色 | 可見範圍 |
|---|---|---|
| **L1** | 一般員工 | 自己的出勤/請假/薪資條/報銷/預支；專案表頭（名稱、技師、有無合約），**不含任何金額** |
| **L2** | 經理 | L1 + **僅自己是 project_members 的專案**之完整資訊（含合約金額、請款進度）；不含他人獎金 |
| **L2.5** | 資深經理 | L2 + 全部專案的表頭與進度（跨案協作用），仍不含獎金 |
| **L3** | 會計/出納 | 全部發票、入帳、放款、報銷、薪資；**獎金金額可見（要匯款）但趴數與計算基礎不可見** |
| **L4** | 老闆 | 全部，含獎金分配矩陣、跨公司金流調度、裁示調整權 |

原規劃「會計看不到獎金趴數」在實作上會卡死——會計要匯款必須知道金額。上表把「知道金額」與「知道計算基礎」拆開，`bonus_allocations.percentage` 對 L3 遮蔽，`bonus_payouts.final_amount` 對 L3 開放。

Supabase 實作：所有敏感表加 RLS policy，L2 的專案隔離用
`exists (select 1 from project_members pm where pm.project_id = t.project_id and pm.employee_id = current_employee_id())`。

## 區塊 L：關係企業往來（代收代付）

已確認：跨公司金流的性質是**集團代收代付**（2026-08-24 使用者確認）。

代收代付要成立，帳必須對得平——B 公司代 A 公司收了 100 萬，B 手上多了現金但那不是 B 的收入，
B 對 A 有一筆應付；A 認列收入並對 B 有一筆應收。**v0 只記了「錢走哪家帳戶」，沒記這筆債權債務，
帳會掛空。**本區塊補上，同時支撐規劃書講的「抵帳」——就是這些往來款互相沖抵。

### 一條紅線：代收代付「只換金流，不換發票」

| | 簽約公司 | 開發票/認列收入 | 收款帳戶 | 性質 |
|---|---|---|---|---|
| 代收代付 | A | **A** | B | ✅ 正常，B 對 A 掛應付 |
| 發票也換 | A | **B** | B | ⚠️ 已非代收代付（屬轉包/聯合承攬/借牌，性質不同） |

原規劃書寫「備註**實際開立收據的公司**」，字面上落在第二列。模型設計成兩種都能存，
但第二種會被 trigger 標記為 `requires_review`，**讓異常可見而不是靜默通過**。

```sql
-- 集團內部往來款流水
create table intercompany_transactions (
  id                  uuid primary key default gen_random_uuid(),
  txn_no              text not null unique,
  txn_type            text not null,
    -- 'collection_on_behalf' 代收：B 代 A 收客戶款 → B 欠 A
    -- 'payment_on_behalf'    代付：B 代 A 付技師/廠商款 → A 欠 B
    -- 'expense_on_behalf'    代墊：B 代 A 支付費用
    -- 'manual'               人工登錄的往來調整
  creditor_company_id uuid not null references companies(id),   -- 應收方（債權）
  debtor_company_id   uuid not null references companies(id),   -- 應付方（債務）
  amount              numeric(14,2) not null check (amount > 0),
  -- ★ 每筆往來都必須指得出是哪筆業務產生的，不允許來源不明的往來
  source_type         text not null,   -- receipt|subcontract_payment|expense|manual
  source_receipt_id   uuid references receipts(id),
  source_payment_id   uuid references subcontract_payments(id),
  source_expense_id   uuid references expense_claims(id),
  project_id          uuid references projects(id),
  occurred_on         date not null,
  settled_on          date,                    -- 全額結清日
  settled_amount      numeric(14,2) not null default 0,
  status              text not null default 'outstanding',   -- outstanding|partial|settled
  requires_review     boolean not null default false,        -- 見上表第二列
  review_reason       text,
  created_at          timestamptz not null default now(),
  notes               text,
  check (creditor_company_id <> debtor_company_id)
);

-- 結清：實際匯款、或與反向往來互抵
create table intercompany_settlements (
  id                    uuid primary key default gen_random_uuid(),
  transaction_id        uuid not null references intercompany_transactions(id),
  settle_method         text not null,   -- 'transfer'實際匯款 | 'offset'互抵 | 'writeoff'
  amount                numeric(14,2) not null check (amount > 0),
  offset_against_id     uuid references intercompany_transactions(id),  -- 互抵時指向被抵那筆
  from_bank_account_id  uuid references bank_accounts(id),
  to_bank_account_id    uuid references bank_accounts(id),
  settled_on            date not null,
  recorded_by           uuid references employees(id),
  approved_by           uuid references employees(id),
  voucher_url           text,
  created_at            timestamptz not null default now()
```

### 自動產生往來的三條規則（trigger）

```
1. receipts 寫入時：
   收款帳戶所屬公司(bank_accounts.company_id) <> 發票開立公司(invoices.issuing_company_id)
   → 產生 collection_on_behalf：creditor = 開票公司，debtor = 收款公司

2. subcontract_payments 寫入時：
   paying_company_id <> subcontract_orders.contracting_company_id
   → 產生 payment_on_behalf：creditor = 付款公司，debtor = 發包公司

3. expense_claims 核銷時：
   reimburse_company_id <> 專案的 contracting_company_id
   → 產生 expense_on_behalf

另加一條檢核（不擋、只標記）：
4. invoices 寫入時：
   issuing_company_id <> projects.contracting_company_id
   → requires_review = true, review_reason = '開票公司與簽約公司不一致，非單純代收代付'
```

### 兩個必要的 view

```sql
-- 帳齡：關係企業往來掛太久，稅上可能被認定為資金貸與而須設算利息
-- （所得稅法 §24-3：營利事業資金貸與他人未收取利息，按貸與期間依規定利率計算利息收入）
-- 所以「這筆掛了幾天」必須看得見，不是等會計師事後發現
create view v_intercompany_aging as
select t.*,
       t.amount - t.settled_amount as outstanding_amount,
       current_date - t.occurred_on as days_outstanding,
       case
         when current_date - t.occurred_on <= 30  then '30天內'
         when current_date - t.occurred_on <= 90  then '31-90天'
         when current_date - t.occurred_on <= 180 then '91-180天'
         else '逾180天 ⚠'
       end as aging_bucket
from intercompany_transactions t
where t.status <> 'settled';

-- 兩兩公司間的淨額（對帳用：龍權淨欠亞斯特多少）
create view v_intercompany_balance as
select creditor_company_id as company_a,
       debtor_company_id   as company_b,
       sum(amount - settled_amount) as net_receivable
from intercompany_transactions
where status <> 'settled'
group by 1, 2;
```

## 關鍵關聯圖（獎金為何必須與請款同時設計）

```
projects (合約金額, 簽約公司)
   │
   ├─→ billing_schedules (第N期, 20%)
   │        └─→ invoices (開票日, ★開票公司)
   │                └─→ receipts (★入帳日, ★收款帳戶)
   │                         │
   │                         ↓ 觸發
   ├─→ bonus_plans ──→ bonus_allocations (經理40% 主辦35% 支援25%)
   │                         └─→ bonus_payouts (由該筆 receipt 觸發, 同比例拆)
   │                                  └─→ payroll_items (掛入當期薪資)
   │
   └─→ subcontract_orders ──→ subcontract_payments (扣繳10% + 補充保費2.11%, ★放款公司/帳戶)
                                        │
   ┌────────────────────────────────────┘
   ↓ 當「實際收/付款公司」≠「開票/發包公司」時自動產生
intercompany_transactions (代收/代付/代墊 → 誰欠誰、多少、掛幾天)
   └─→ intercompany_settlements (實際匯款結清 or 反向往來互抵)
```

★ = 三個獨立的「哪家公司」維度。規劃書想用備註欄解決，那樣無法查詢、無法對帳；改用外鍵後，「這個月龍權帳戶進出多少」是一句 SQL。

## v0 的已知缺口

1. `billing_schedules.calculated_amount` 目前寫成 placeholder，實際要用 trigger 依 `projects.contract_amount × percentage` 計算，並在合約變更（change_order）時重算未請款期數。
2. 加班費費率、勞健保級距表、扣繳率屬**會變動的法規參數**，須抽成 `system_parameters` 設定表並帶生效日，不可寫死在程式裡。
3. 跨年度專案的營收認列與獎金結轉尚未建模（工程案 2–4 年必然跨年度）。
4. 多公司合併報表的科目對應未建模。關係企業已確認為代收代付（區塊 L 已處理往來款），
   合併報表屬會計師作業範圍，暫不納入系統；若後續要做，資料已具備（往來款可辨識並沖銷）。
